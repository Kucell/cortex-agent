## 中文版

### 重大特性 (Major Features)

#### 1. P-006 Cross-Project Automation Pipeline — 5 项能力全 ship
**把 proposal 审批、mission 落地、inbox 监听、emit-on-done、gate 验证拼成一个完整闭环,使跨项目协调完全自动化。**

##### Capability A: bridge emit (生产者侧 SDK + CLI)
- `lib/cross-project/outbox.js` (172 行): schema 验证写入、原子 temp+rename、速率限制、确定性 event id 生成、`readEvents` / `deleteEvent` 配 mtime-based since 过滤
- `lib/commands/bridge.js` 扩展: 新增 `emit` / `outbox-list` / `outbox-prune` 子命令,扩展 `--type` / `--summary` / `--id` / `--propagated-at` / `--before` 解析

##### Capability B: materialise-mission (proposal → mission 骨架)
- `lib/automation/proposal-to-mission.js` (293 行): frontmatter parser(YAML 子集 + inline list + 多行列表)、mission id deriver、milestone 脚手架、`mission-plan.md` / `validation-contract.json` / `command-log.md` / `handoffs/README.md` writer

##### Capability C: watch-inbox (inbox → 下游 mission dispatch)
- `lib/automation/inbox-listener.js` (161 行): 从 `.agent/bridges/<id>.json` 加载 handler,`planDispatch` 带 `correlation_group` 过滤,dispatch sidecar writer,cursor (after-semantic, propagated_at + bridge_event_id tie-break) 保证重跑不重复 dispatch

##### Capability D: emit-on-done (mission 完成 → 自动 emit bridge event)
- `lib/automation/mission-completion-hook.js` (121 行): 验证 `mission-plan` frontmatter 的 `bridge_emit_on_done` 和 `validation-contract.json` 的 `bridge_emit` gates,把 `checkpoint.closed` 事件合成到 outbox

##### Capability E: bridge_sync gate validation
- `lib/automation/proposal-to-bridge-gate.js` (55 行): `deriveBridgeSyncGate` 从 proposal frontmatter 的 `cross_project_peers` 合成一个 `bridge_sync` gate
- `proposal-to-mission.js` 把它接到 `validation-contract.json`

##### Capability F: automation CLI 集成
- `lib/commands/automation.js` (196 行): 子命令 `materialise-mission` / `emit-on-done` / `watch-inbox` / `approve-and-launch` + `help`
- `bin/cli.js` + `lib/commands.js` + `lib/cli/contract.js` 全链路注册 (含 machine-readable contract 同步)

## English Version

### Major Features

#### 1. P-006 Cross-Project Automation Pipeline — 5 capabilities shipped

##### Capability A: bridge emit (producer side SDK + CLI)
- `lib/cross-project/outbox.js` (172 LOC): schema-validated writes, atomic temp+rename, rate-limit, deterministic event id generation, `readEvents` / `deleteEvent` with mtime-based since filter
- `lib/commands/bridge.js` extended: new sub-commands `emit` / `outbox-list` / `outbox-prune`; extended flag parsing for `--type` / `--summary` / `--id` / `--propagated-at` / `--before`

##### Capability B: materialise-mission (proposal → mission skeleton)
- `lib/automation/proposal-to-mission.js` (293 LOC): frontmatter parser (YAML subset + inline list + multi-line list), mission id deriver, milestone scaffolding, `mission-plan.md` / `validation-contract.json` / `command-log.md` / `handoffs/README.md` writer

##### Capability C: watch-inbox (inbox → downstream mission dispatch)
- `lib/automation/inbox-listener.js` (161 LOC): handler loaders from `.agent/bridges/<id>.json`, `planDispatch` with `correlation_group` filter, dispatch sidecar writer, cursor (after-semantic, propagated_at + bridge_event_id tie-break) so re-runs don't re-dispatch

##### Capability D: emit-on-done (mission completion → auto-emit bridge event)
- `lib/automation/mission-completion-hook.js` (121 LOC): validates `mission-plan` frontmatter `bridge_emit_on_done` and `validation-contract.json` `bridge_emit` gates, synthesises `checkpoint.closed` events into the outbox

##### Capability E: bridge_sync gate validation
- `lib/automation/proposal-to-bridge-gate.js` (55 LOC): `deriveBridgeSyncGate` synthesises a `bridge_sync` gate from `cross_project_peers` in proposal frontmatter
- `proposal-to-mission.js` wires it into `validation-contract.json`

##### Capability F: automation CLI integration
- `lib/commands/automation.js` (196 LOC): sub-commands `materialise-mission` / `emit-on-done` / `watch-inbox` / `approve-and-launch` + `help`
- Full registration through `bin/cli.js` + `lib/commands.js` + `lib/cli/contract.js`
