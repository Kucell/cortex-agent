## Product identity

**Cortex Agent — A Governed, AI-Native Development Harness.**

**业务属于项目，推理属于 AI，开发治理、自动化维护与持续演进机制属于 Cortex。**

Cortex maintains the governance and automation protocol for AI-assisted development across projects with different business domains. The project supplies its business context, domain rules, assets and test contracts. An already-connected AI Host supplies reasoning, software design and coding ability. Cortex supplies controlled Task/Plan/Artifact execution, permission and approval boundaries, reviews, reproducible evidence, versioned updates and continual governed improvement.

Cortex is **not** an LLM, standalone inference engine, domain business agent, extra AI provider SDK, replacement coding Host or autonomous authority.

### Ownership rules

- **L1 framework:** generic development policies, schema, provider-neutral integration, upgrade and release process.
- **L2 each project:** project-specific domain logic, private memory, industry regulations, test fixtures and customer data.
- **L3 Cortex self-bootstrap:** Cortex development's internal health, regression and self-upgrade process; not distributed automatically.
- **AI Host:** reasoning and coding within the Host's declared capabilities, scoped by Cortex's explicit authorization. Host/tool capability is not permission.

**Project iteration:** business-specific improvements stay with the project unless there is a separate authorized reason to abstract them.

**Framework iteration:** only independently verified reusable engineering invariants can be promoted to generic Cortex rules. The framework must not silently ingest other projects' raw business knowledge.

The four modules already exist, but some planned trigger, reasoned-handoff, recovery and full end-to-end integrations are **not yet verified**. v1.16.0 must connect them without introducing a new model inference layer or a second execution state machine.

## Design invariants

1. **Evidence before inference:** source revision, real tool result and provenance mandatory; absence of observability is not success.
2. **AI suggestions are untrusted input:** closed-schema handoff, path/permission allowlists, explicit deadlines and budgets, independent validation.
3. **Existing governance remains authoritative:** Task, Run, Artifact, Decision/Waitpoint and scoped CAS; no automatic privilege escalation or inferred merge/release authorization.
4. **Private project domain isolation:** explicit opt-in for cross-project aggregate insights; de-identification, consent and audit; no raw transcripts or credentials in generic framework.
5. **Host neutral:** reuse RuntimePort and current adapters; unsupported capabilities degrade to deferred/manual, never silent provider substitution.
6. **Safe evolution:** additive upgrade, managed update, local customization preservation, repeatable rollback and real self-check health.
