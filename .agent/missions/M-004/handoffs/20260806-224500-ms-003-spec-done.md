## Scope

### 必做 (Mandatory)

#### F-006 — parent-resume client (`lib/event-bus/clients/parent-resume.js` 新文件, ~250-300 行)

- **FSM 5 状态**: `INIT` → `RECEIVED` → `ACKED` → `RUNNING` → `DONE` / `FAILED`
- **触发 event**: 8 类 core event 中 `eb:subagent_completed` / `eb:subagent_failed` / `eb:subagent_cancelled` 触发 RESUME,其他 (spawned/progress) 触发 state transition 但不 resume
- **API**:
  - `parentResume.handle(event, ctx) → { ack: true|false, next_state, resume_action }`
  - `parentResume.subscribe(bus, mission_id) → subscription_handle`
  - `parentResume.unsubscribe(subscription_handle) → boolean`
  - `parentResume.listActive() → Array<{ mission_id, subagent_id, state, last_event_at }>`
- **P-003 整合**:
  - 父 agent 收到 `eb:subagent_completed` → 写 P-003 inbox (`lib/cross-project/inbox-store.js`) 让 P-003 bridge 自动 sync
  - 父 agent resume mission 走 P-003 subscriptions (`lib/cross-project/subscriptions.js`) 验证
  - 父 mission_id 跟 P-003 source-id 双向绑定 (e.g. mission_id = `M-004-MS-003`, source-id = `M-004-MS-003`)
- **mavis 平台桥接** (D-FAE-002-5):
  - framework emit `eb:subagent_completed` → mavis 知道 (本地读 inbox 即可,不需要 emit 到 mavis)
  - mavis task tool 完成 → framework 也 emit `eb:subagent_completed` (M-008 触发)
  - 桥接 1 处:`lib/event-bus/clients/parent-resume.js` handle 里 listen mavis inbox topic
- **Lease 校验** (D-FAE-002-4):
  - 父 mission_id 必须有 active lease (从 `.agent-runtime/coordination/leases.json` 读)
  - lease 失效 / 错配 → 3 次 retry + 写 decision `.agent/decisions/D-ESC-<mission_id>-<ts>.json` 让 Eric 人工介入
- **安全**:
  - 拒绝 mission_id 不在 `.agent/missions/` 的 event (避免恶意 mission 触发 resume)
  - 拒绝 parent_id 跟 active mission 不匹配的 event (避免 parent 误 resume 错 mission)

#### F-007 — E2E 验证 (`tests/event-bus-parent-resume-e2e.test.js` 新文件, ~300-400 行)

- **场景 A**: 父 mission `M-TEST-MS003-A` 派 3 sub-agent 并行 (claude-code adapter) → 父自动 resume (3 sub 全部 completed)
- **场景 B**: 父 mission 派 3 sub, 其中 1 failed → 父 resume + 写决策 escalate (D-FAE-002-4)
- **场景 C**: 父 mission 派 3 sub, 1 cancelled + 2 completed → 父 resume (cancel 不阻止 resume)
- **场景 D**: parent-resume 跟 P-003 bridge 整合 — P-003 inbox 收到 3 sub 完成后自动 sync 到远端 (mock source)
- **7 关键断言**:
  1. 父 FSM `INIT → RECEIVED → ACKED → RUNNING → DONE` 5 状态全过
  2. 3 sub-agent 全部完成前父 RUNNING,完成后转 DONE
  3. failed sub 触发 escalate decision 写盘
  4. P-003 inbox 收到 3 个 sub 事件 (1 个 event per sub)
  5. P-003 bridge sync mock 收到 1 次 sync 调用 (聚合 3 event)
  6. 父 mission_id + lease 校验通过
  7. 父 unsubscribe 后不再接收后续 event

#### F-006b — client registry (`lib/event-bus/clients/index.js` 新文件, ~30 行)

- `clients.register(name, handler)` — 注册 client
- `clients.handle(event, ctx)` — fan-out to all registered clients
- `clients.list() → Array<{ name, handler }>`
- 内置: parent-resume (default), coordination-sync (MS-004 实施时加), dashboard-push (MS-004 实施时加), notification-pump (MS-004 实施时加)

#### F-006c — CLI 扩展 (`lib/event-bus/cli.js` + `bin/cli.js`)

  - `cortex-agent event-bus resume --mission-id <id>` — 列当前 mission 的 active sub + state
  - `cortex-agent event-bus resume --mission-id <id> --force` — 强制 retry escalate decision
- 集成方式: 严格 additive, `bin/cli.js` +5-10 行 (新 case "event-bus resume" forward, 或扩 eventBusCommand dispatcher)
