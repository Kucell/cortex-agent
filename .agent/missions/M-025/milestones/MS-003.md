## Collection Boundary

- Do not read or persist prompt, response, transcript, tool payload, source body, credentials or Host private paths.
- Do not infer missing usage, mix estimated values into Host-reported totals, or publish savings before VC-016 passes.
- Do not change model, context, compression, routing, fan-out, retry, timeout or stop policy.
- Do not launch repeated Host calls until an exact cadence, maximum call count, Host/model cohort, time window and cost boundary are approved.

## Execution Plan

### Phase A: passive collection readiness

- Add a zero-dependency, dependency-injected collector that accepts only an already-sanitized public usage envelope.
- Reuse the MS-001 receipt contract and ledger writer; do not fork or weaken their schema/security checks.
- Join quality dimensions through allowlisted Task/Run identifiers and focused projections; do not add bodies to receipts.
- Add readiness queries for eligible non-test receipt counts by Host/day/model and explicit exclusion reasons.
- Collector must never spawn a Host, read private Host storage, or change execution policy.
- Governed Pi may implement only the scoped collector/query/tests and must stop at `READY_FOR_REVIEW`; worker output is not validation evidence.

### Phase B: seven-day observation

- Prefer passive observation of organic governed tasks; collector itself creates no model calls.
- The seven-day window starts only when both Hosts have an eligible receipt on the same UTC day.
- Synthetic probes, tests, unknown/unavailable usage and duplicate receipts do not count toward VC-016.
- If organic traffic cannot reach 100 eligible receipts per Host, any generated workload requires a separate external-side-effect Decision with a call and cost cap.
- Collection entry: `scripts/capture-usage.js` accepts one already-sanitized public usage
  envelope (JSON on stdin) and writes a MS-001 receipt into `.agent/token-attempts/`;
  test-prefixed attempts are excluded automatically. Dry-run with `--dry-run`.
  Baseline integrity verified 2026-08-14: synthetic verification receipts removed,
  `queryReadiness` shows `eligible_count: 0`.

### Phase C: independent evaluation

- Evaluation protocol is pre-frozen in `handoffs/phase-c-evaluation-framework.md`
  (proposal-only preparation artifact; does not approve or activate P-002/P-003/P-004,
  which remain `draft` until a new Decision).
- Root freezes cohort, policy revision, Host/model dimensions and UTC query window before calculation.
- Quality, retry/reread and missing-context outcomes are reported alongside token aggregates.
- Estimated cost is labelled separately; unknown usage is excluded, never converted to zero savings.
- Recommendations for P-002/P-003/P-004 remain proposal-only until a new Decision is approved.
